# ak820-display-watcher

Фоновый сервис для Windows: гасит подсветку клавиатуры **AJAZZ AK820** (`320F:505B`), когда
изображение на экранах пропадает (таймаут монитора, кнопка питания, сон системы), и возвращает
прежний вид подсветки при пробуждении экрана.

Блокировка сеанса (`Win + L`) подсветку **не гасит**: на экране ввода пароля клавиатура должна
светиться — утром в темноте это единственный ориентир. Клавиатура выключается только вместе с
изображением на экране.

Монитор, выключенный **физической кнопкой**, не отслеживается: Windows об этом не сообщает, а
опрос мониторов по DDC/CI удалён — он сам будил спящие экраны и давал ложные срабатывания.

Работает без окна и без консоли, в простое не потребляет CPU (ожидание событий Windows через
блокирующий цикл сообщений `GetMessageW`).

## Сборка

```cmd
build.cmd
```

Бинарник: `target\release\ak820-display-watcher.exe`.

`cargo build --release` вручную тоже работает, но только из окружения Visual Studio
(`vcvars64.bat`): без него компилятор C-части `hidapi` падает с ошибкой `D8050`.
Профиль **debug** в этой системе не собирается — `cc-rs` добавляет `-Z7`, поэтому используйте
`release`.

## Запуск

Запустите `target\release\ak820-display-watcher.exe`. Консольного окна не будет — это
GUI-приложение. Второй экземпляр сразу завершается (именованный мьютекс).

Журнал пишется рядом с exe: `ak820-display-watcher.log`.

### Автозагрузка

Запустите `autostart.bat` и выберите пункт:

```
[1] Enable autostart   (start with Windows)
[2] Disable autostart  (remove from startup)
```

Скрипт создаёт или удаляет ярлык в папке автозагрузки текущего пользователя, поэтому права
администратора не нужны. Для автоматизации есть аргументы: `autostart.bat enable`,
`autostart.bat disable`, `autostart.bat status`.

Ярлык виден в Диспетчере задач на вкладке «Автозагрузка», где его можно отключить и без скрипта.

## Что и как делает

1. Создаёт message-only окно (`HWND_MESSAGE`) и подписывается на:
   - `GUID_CONSOLE_DISPLAY_STATE`, `GUID_MONITOR_POWER_ON` — питание дисплеев;
   - `GUID_SESSION_DISPLAY_STATUS` — только для журнала, на решение не влияет;
   - `WTSRegisterSessionNotification` — блокировка и разблокировка, тоже только для журнала;
   - `WM_DISPLAYCHANGE` — смена топологии мониторов;
   - `WM_POWERBROADCAST` — сон и пробуждение системы.
2. Держит независимые флаги и отправляет команду только при изменении их сочетания:
   ```rust
   display_sleeping || monitors_disconnected || screens_dark
   ```
   `session_locked` в это условие намеренно не входит, поэтому `Win + L` ничего не гасит.
3. Раз в 10 секунд сравнивает время бездействия с таймаутом отключения экрана из плана
   питания. Windows гасит панели ровно при достижении таймаута, поэтому превышение означает:
   изображения нет. Полноэкранный Direct3D и режим презентации исключаются — они держат дисплей
   включённым вопреки бездействию.
4. При выключении читает конфигурацию клавиатуры (29 байт), сохраняет её (в памяти и на диске),
   обнуляет байт яркости и записывает обратно. При восстановлении записывает сохранённый конфиг
   целиком, поэтому режим, цвет и скорость остаются прежними. Файл на диске нужен на случай
   отключения питания: без него клавиатура осталась бы тёмной после включения компьютера.

## Протокол

Клавиатура использует вендорский HID-интерфейс `Usage Page 0xFF1C / Usage 0x0092`.
Пакет — 64 байта:

| Байт | Значение |
|------|----------|
| 0 | `0x04` report ID |
| 1–2 | контрольная сумма (16-битная сумма байтов 3..63, little-endian) |
| 3 | код команды |
| 4 | длина полезной нагрузки |
| 5–6 | смещение, little-endian |
| 7 | `0x00` |
| 8..63 | полезная нагрузка, до 56 байт |

Коды команд: `BEGIN` `0x01`, `END` `0x02`, `READ_CONFIG` `0x05`, `WRITE_CONFIG` `0x06`.
Яркость — байт 2 конфигурации: `0` выключает подсветку, `4` — максимум.

Каждый пакет подтверждается ответом (`read_timeout`, 1000 мс); байт 7 ответа `0xFF` или `0xFE`
означает отказ.

## Диагностика

`cargo run --release --example probe` — открывает клавиатуру, читает конфигурацию, гасит
подсветку на две секунды и возвращает исходный конфиг. Показывает список HID-интерфейсов и
выбранный.

`cargo run --release --example readcfg` — печатает текущий 29-байтный конфиг клавиатуры и
декодированную яркость, ничего не меняя. Удобно, чтобы понять, в каком состоянии клавиатура.

Дополнительно см. `TA.txt` — техническое задание с описанием требований и протокола.

## Замечание о скорости

`HidApi::new()` на этой машине занимает около 10 секунд (перечисление HID-устройств),
открытие самого устройства — единицы миллисекунд. Поэтому соединение устанавливается при
старте сервиса, в отдельном рабочем потоке; момент блокировки экрана его не ждёт.

## Память

Размер exe (около 200 КБ) и потребление памяти — разные вещи: процесс отображает в себя
системные библиотеки, которые сами по себе весят десятки мегабайт. Здесь они общие и уже
находятся в памяти для других процессов.

Замеры в установившемся режиме:

| Показатель | Значение |
|---|---|
| Рабочий набор (Task Manager) | ~1.9 МБ |
| Приватная память | ~2.4 МБ |
| CPU в простое | 0 мс |

Что повлияло на цифры:

- **Сжатие рабочего набора** (`SetProcessWorkingSetSizeEx`) после инициализации и после
  каждой команды: 9.2 МБ → 1.9 МБ. Это убирает из процесса страницы библиотек, к которым он
  больше не обращается; сама память системы при этом не освобождается, потому что страницы
  общие. При следующем обращении они подгружаются обратно.
- **Стеки потоков** уменьшены с 2 МБ до 128 КБ (`Builder::stack_size`). Экономит резерв
  адресного пространства, а не резидентную память: стек занимает только то, что реально
  использовано.
- **Освобождение списка HID-устройств** после открытия клавиатуры: `HidApi` хранит
  перечисление всех HID-устройств системы, а открытый `HidDevice` от него не зависит.

Уже было выставлено заранее: `panic = "abort"`, `lto = true`, `opt-level = "s"`, `strip = true`.

Что остаётся в основе 2.4 МБ приватной памяти: `SETUPAPI.dll` (перечисление HID), `user32`,
`combase`, `crypt32` и прочие библиотеки, отображённые процессом. Без HID-перечисления и окон
сообщений их не убрать — а без них не будет ни клавиатуры, ни событий Windows.

Если в процессе видна `RTSSHooks64.dll` (RivaTuner / MSI Afterburner), это внедрённая
сторонняя библиотека: она добавляет к рабочему набору около 2.5 МБ. Приложение можно исключить
в настройках RTSS.
